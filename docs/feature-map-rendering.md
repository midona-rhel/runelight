# Rendering, water, materials, scene management and tools

Source audit of the current working tree, 2026-11-07. This describes implemented behavior, not visual acceptance or measured performance. Defaults below are declaration defaults, not necessarily the user's saved settings. Lighting and weather have separate maps. No live-game tests were performed for this document. Historical inventory documents and shader comments reporting old timings are not treated as current measurements.

## How the picture is assembled

The scene first supplies opaque color, normal, depth and material buffers. Transparent geometry is shaded while drawn into a separate layer. Water has an actual surface geometry pass as well as lowered terrain underneath it. Screen-space effects and lighting then feed the composite; weather and the spatial upscaler operate before the full-resolution game interface.

| Feature | What actually happens | Controls and interactions | Limits / questions to inspect in play |
|---|---|---|---|
| Scene resolution | Geometry and the main composite render at a selected fraction of window resolution. | `renderScale`: 100% default, 75%, 50%, 25%, or 1x without HiDPI scaling. 1x divides by backing scale on HiDPI displays. | This is not a global multiplier for every effect's pixel count. The AO, directional-visibility and cloud intermediates retain their existing resolution policy. Water shading is now ceil(3D scene width / 2) by ceil(3D scene height / 2), independent of window resolution; its surface geometry and final composition use the 3D scene resolution. Fog remains at most half scene resolution. |
| Spatial upscale | Five-tap Catmull–Rom reconstruction mixed with bilinear, clamped to the surrounding four texels' color range to avoid overshoot. | `upscaleSharpness` 0–100%, default 40. Zero gives bilinear. Only relevant below full scale. UI is drawn afterward at full resolution. | No temporal reconstruction or motion-vector recovery. Fine details lost at low scene resolution cannot be recovered. |
| MSAA | Color, normals, depth, materials and transparent coverage retain multiple samples. Main composite shades the first surface; an edge pass shades samples classified as another surface. | Default 2x; disabled, 2x, 4x, 8x, 16x. Actual count is clamped to driver texture/depth/sample limits; forced driver samples take precedence. | Second-surface samples are grouped using depth/normal/material tolerances, not separately shaded without limit. Other screen-space passes largely use sample zero. Test thin fences, overlapping leaves, water edges and transparent intersections. Saved requested MSAA can differ from actual MSAA. |
| Texture filtering | Close texels remain nearest filtered. Positive filtering levels enable mipmaps with interpolation between mip levels. | Anisotropic level 0–16, default 8. Zero disables mipmap minification too; one enables mipmaps without anisotropy. Extension/driver limit clamps anisotropy. Reduced render scale adjusts mip LOD bias. | This setting changes two behaviors, not just anisotropy. Zero can increase distant texture shimmer. Hardware vendors may implement anisotropy differently. |
| UI scaling | Separate selectable UI reconstruction. | Hybrid default; nearest, linear, Mitchell, Catmull–Rom, xBR or hybrid. Changing mode recompiles shaders. | Independent of scene upscale sharpness. Check text and icon edges at the actual Windows display scale. |
| Smooth color bands | Interpolates HSL-derived color in the scene fragment shader instead of leaving coarse interpolated vertex RGB bands. | `smoothBanding` default true. | Appearance adjustment; does not add geometry or recover detail. |
| Bright textures | Compatibility choice for the older brighter texture lighting. | `brightTextures` default false. | Do not confuse with light intensity or display exposure. |
| Color-blind adjustment | Shader-selectable color transformation with adjustable amount. | Mode defaults none; intensity 0–100%, default 100. Mode change recompiles shaders. | A visual transform, not a replacement material palette or a guarantee every gameplay cue becomes distinguishable. |
| Vertex snapping | GPU flag controlling whether original vertex snapping is retained. | `removeVertexSnapping` default true; updates GPU flags. | Motion/geometry presentation behavior, separate from MSAA. |

Opaque buffers use RGBA8 color, RGB10_A2 normals, depth32F and RGBA8 material data. Separate diagnostic light buffers use RGBA16F. Lighting performs linear/sRGB conversions in several composition paths; the existence of a floating-point diagnostic buffer does not mean the entire rendering pipeline is an unclipped HDR pipeline. There is no exposed general exposure, bloom or tone-mapping control in `LuminaConfig`.

Transparent objects use premultiplied layer composition and disable depth writes during their draw. The transparent directional-shadow path binds the previous frame's shadow texture/matrix. This is a specific temporal difference from opaque composition, not proof of a visible defect; inspect moving camera/light transitions before changing it.

## Water: surface, bed, flow and reflections

| Behavior | Current implementation | Parameters and interactions | Limits |
|---|---|---|---|
| Water presence | Imported texture and environment classifications identify fresh water, ocean variants, swamp and cave water. A mesh supplies the visible surface; terrain beneath it is lowered into a bed. | `water` default true. Toggling it triggers scene reload because bed geometry is baked during upload. | Classification depends on shipped data and heuristics. WaterMap's introductory claim that the surface is not geometry is stale; `WaterSurface` is active. |
| Depth and shore | Bed depth increases with distance from shore, up to eight tiles. Minimum depth is 56 world units; the eight depth steps are 82, 165, 258, 335, 385, 412, 451 and 506. | One tile is 128 world units. Data build limits neighborhood dependencies so reused zones align with newly uploaded neighbors. | A constructed bed, not actual terrain bathymetry or a fluid simulation. Bed depth strongly changes apparent tint, clarity and caustics. |
| Surface appearance | Surface geometry at the selected 3D scene resolution records normal/type/foam/depth/caustic information. Surface lighting runs at half that width and height, rounded up, then combines with the bed at scene-resolution edges. | Up to 32 water-look slots per scene. Most appearance constants are shader/data values rather than settings. | Both water targets now follow 3D render scale. This implemented sizing fix does not establish that the reported rock depth sorting or moving-water pixel crawl is resolved; matched visual acceptance remains pending. |
| Transmission and opacity | Looking down reveals shallow tinted bed; grazing angles gain Fresnel reflection. Depth and soft waterline factors change opacity. | Fresnel base 0.15, power 2; depth scale 64 world units; soft-waterline scale 48. | These are artistic constants, not physical water parameters or adjustable UI controls. |
| Flow | Shipped `water_flow.dat` contains precomputed world flow, version 3 at 2x2 samples per tile. Missing/invalid data falls back to local scene inference. | Compressed regions load lazily with a 32-region cache. Encoded speed unit is 0.01 tile/s. | Different fallback behavior is possible where world data is absent. Flow is prescribed rather than solved at runtime. |
| Waterfalls | Terrain drops of at least one tile with water on both sides identify falls. Lip and foot influence nearby flow and turbulence. | Lip reach 2.5 tiles, foot reach 3 tiles; representative speeds 1.2 tiles/s at lip, 2.56 falling, 0.8 at foot. | A dry bank must not become a waterfall. Inspect unusual banks, artificial channels and vertically stacked water. |
| Object interaction | Static objects standing in water supply contact information that slows local flow and raises turbulence. | Four contact samples per tile; reach three cells; 48-world-unit hover tolerance. | This is a sampled static contact field, not dynamic collision-driven fluid displacement. |
| Wave drift | Motion uses a monotonic clock and integrated drift, preventing velocity changes from jumping the whole phase. Wind follows over about 1.5 seconds. | Calm drift 5 world units/s plus wind contribution 18. Motion wraps on a 3840-second period. | Wind, flow and weather can change appearance without changing any water setting. |
| World reflections | Screen-space depth tracing looks for already-rendered scene geometry. | `waterReflections` default true. Four expanding trace steps, starting at 96 world units, then three refinement steps. | Cannot reflect geometry offscreen or hidden behind other visible geometry. The toggle disables world tracing, not all sky reflection. |
| Sky and cave reflection | Water reflects sky independently from the world trace; cave water uses a dark cave/fog tint. | Sky/day/night and environment state affect water. Outdoor eligibility depends in part on `sunLighting` through frame state. | A water comparison with different lighting/environment flags is not an isolated water comparison. |
| Glints and caustics | Sun/moon specular glints; shallow-bed caustics sample the imported caustics texture and drift with flow. Point lights can produce streaks using shared point-light occlusion. | `waterCaustics` default true. Caustic fade spans roughly 24–260 world units of depth; direct-light scale 1.1; moon contribution scaled 0.35. Clouds suppress glints. | No separate controls for wave amplitude, flow speed, Fresnel, depth tint or caustic strength. Point-light streak behavior belongs to the shared lighting path, not an independent light list. |
| AO and weather | AO follows water surface and fades under water; rain, foam, waves and wind interact with weather. | See weather map for precipitation and buildup controls. | Water rendering, weather and geometry upload are coupled; changing several at once obscures the source of artifacts. |

## Materials and vegetation

Materials are lightweight flags carried alongside game texture/vertex data, with imported 117HD-derived object and face rules. They are not a general PBR material authoring system. Imported provenance does not establish parity with today's upstream 117HD dataset.

| Behavior | Implementation and controls | Important limits |
|---|---|---|
| Model shading | Game normals, flat-face rules and imported overrides determine normals. Vanilla's baked directional shading is approximately undone before new lighting. Textured faces use fixed lightness 90. | Dark/flat exceptions and retained-vanilla-shading rules mean not every surface follows identical processing. Normal encoding is quantized, and undoing baked shading is approximate. |
| Material overrides | Imported rules select objects and sometimes individual faces by hue/saturation/lightness, transparency and texture presence. Flags include emissive level, thin-leaf transmission, water/bed and snow classes. | Color-based classification can misclassify unusual content. This is worth inspecting before adjusting global illumination to fix one object. |
| Emissive faces | A 0–3 level mixes ordinary surface illumination toward a self-lit value, scaled by `emissiveStrength` (default 100%, range 0–300%). Flags remain baked even if strength is zero. | Emissive appearance does not itself spawn a point light, illuminate neighboring geometry or create bloom. Actual point-light placement is a separate system. |
| Leaves | `leafTransmission` defaults true. Thin-face backlighting contributes according to opposite light direction and viewing direction. Bark/gray exclusions use color heuristics. | Artistic thin-leaf lighting, not subsurface volume transport. A bright tree canopy may come from transmission rather than a point light. |
| Wind sway | Listed object IDs and imported modes determine bend, jiggle and anchors. Tree lower quarter stays anchored; tree bend grows quadratically, plant bend with height power 1.5. Small plants get reduced bend. | Only listed content participates. Already-animated dynamic objects do not receive this additional wind sway. Import errors can explain rigid or wrongly bending scenery. |
| Wind control | `windSway` defaults true; toggling changes uniforms without scene reload. Weather supplies wind direction and gust behavior. | Per-vertex weights and modes are baked on upload, whereas wind amount is live. Some shared anchor metadata is also used for snow, so deleting it as 'wind-only' would break another feature. |
| Small model water | Certain textured model faces (e.g. fountains, wells/troughs or falls) are classified as fake water and converted to textureless opaque surfaces with encoded depth. | This is a special material route into water shading, distinct from terrain water detection. Test both when changing water. |

Sources: [SurfaceMaterials.java](../src/main/java/com/midonarhel/lumina/scene/SurfaceMaterials.java), [VertexShading.java](../src/main/java/com/midonarhel/lumina/scene/VertexShading.java), [WindSway.java](../src/main/java/com/midonarhel/lumina/scene/WindSway.java), [materials.glsl](../src/main/resources/com/midonarhel/lumina/materials.glsl).

## Scene loading, distance and map hiding

`drawDistance` is 50 tiles by default, adjustable 0–184. It controls visibility distance, while expanded map loading adds actual map chunks available to render: default three extra 8-tile chunks, range zero to five. Their costs are related but they are not interchangeable. The edge fade is centered on camera focal position and the requested client scene distance accounts for camera offset.

Scene loading builds an atomic derived bundle of scene zones, roof changes, water and fog-ground data. Voxel and static-shadow builds may finish later; old derived state can stand in until they complete. Reusing zones avoids rebuilding everything, but introduces dependencies between cached geometry and derived lighting/water state. This is an important place to inspect reload symptoms before treating them as shader problems.

CPU upload preparation has a separate fixed worker count of up to three, derived from CPU availability. This is not the `numThreads` setting: that setting defaults to three (0–15) and rebuilds the dynamic-model rendering worker structures plus GPU flags.

OpenGL scene jobs run on the client thread after presentation, prioritized LOAD, SHOWN, UPKEEP. Normal deadline is 1 ms; load work during the loading state gets 4 ms. The deadline is cooperative and each step can execute at least one unit, so **these are scheduling budgets, not proven upper bounds on frame cost**. Exceptions log and end that job rather than guaranteeing successful completion.

| Map control | Behavior | Change behavior / limitation |
|---|---|---|
| `hideOtherAreas` (true) | Imported area boxes and unhide exceptions remove tiles before geometry, water, lights and voxel derivation. Moving across an area boundary can reload the scene. | Setting change explicitly reloads while logged in. It can affect lighting indirectly by changing the input scene. |
| `hideUnrelatedMaps` (true) | Region table compares chunks against the central region and removes unrelated regions. Disabled for instances. | Applied during preparation; unlike `hideOtherAreas`, its config-change handler has no immediate reload branch. New value may await a natural reload. |
| Expanded map chunks | Changes client map loading extent. | Explicitly sets loading state while logged in. More loaded content can increase preparation/memory as well as render opportunities. |

## Presentation, platform behavior and performance evidence

| Item | Actual behavior | What it means for comparisons |
|---|---|---|
| Unlock FPS | Default true; controls client unlocked rendering. Disabled returns to client 50 FPS timing and forces sync off. | A 20 ms frame interval while locked does not prove 20 ms rendering work. |
| VSync | Off by default; on requests swap interval 1, adaptive requests -1. Platform/context reports the actual interval. | Requested and actual sync can differ. Record actual state. |
| FPS target | Default 60, range 1–999; only applied when actual swap interval is zero and FPS is unlocked. | A capped 16.7 ms interval includes waiting. Use separate active CPU/GPU durations to compare renderer work. |
| GL requirements | Startup requires OpenGL 3.3. OpenGL 4.5 enables zero-to-one clip control; older path retains alternate depth conventions. | Windows and macOS can use distinct depth and capability paths. A shader compiling on one driver does not validate the other. |
| Pixel format | Current Windows path requests zero stencil bits in the window pixel format; other platform path requests eight. | Scene/offscreen stencil handling is separate. Startup compatibility and scene rendering must be checked independently. |
| Saved settings | Config group remains `runelight` despite Lumina rename. Existing profile choices persist. | Defaults in this map cannot be substituted for the running Windows profile. |
| Shader reload | UI scaling mode, color-blind mode and diagnostic view changes reload shaders; the reload path is designed to retain old programs on failure and restore texture animations. | A failed reload may leave previous shader behavior visible. Compile logs are necessary evidence. |
| GL error checks | Default false; enables frequent synchronous error queries. | Useful for diagnosis, but leave off for representative performance measurements. |
| Frame snapshot | Records time between presented frames and writes CSV plus mean, median, p95, maximum and hitch counts. Hitch threshold is 1.5 times median. | Measures delivered pacing, including waits/scheduling. Does not isolate point-light cost or shader execution. |
| GPU sections | Optional `GL_TIME_ELAPSED` queries measure named sections. Result reads wait for GPU completion. Optional serial mode calls `glFinish` at every section boundary. | Serial mode deliberately changes overlap and scheduling; those numbers are not ordinary-play timings. Query-read synchronization can also change pacing. Primitive-count mode measures counts, not milliseconds. |

Sources: [LuminaPlugin.java](../src/main/java/com/midonarhel/lumina/LuminaPlugin.java), [LuminaConfig.java](../src/main/java/com/midonarhel/lumina/LuminaConfig.java), [FrameSnapshot.java](../src/main/java/com/midonarhel/lumina/dev/FrameSnapshot.java), [GpuSections.java](../src/main/java/com/midonarhel/lumina/dev/GpuSections.java).

No specific historical 6.9 ms figure is validated by this audit. A useful measurement report must identify live scene/camera, resolution and display scale, actual MSAA, actual cap/sync, enabled features, warm-up, measurement API, sample count and distribution. A shader comment describing an earlier speedup is neither a reproducible experiment nor proof that the same bottleneck exists on this PC.

## Developer views and coverage boundaries

The main diagnostic selector offers Final, Depth, Normals, Ambient occlusion, Shadows, Lighting, Light clusters, Materials and Skylight. Water has a separate selector: Off, Types and flow, Waves. These expose intermediate representations, not automatic correctness tests. Weather field map and building visualization are separate overlays; strike-lightning is a momentary action that resets its setting. These controls are off/final by default.

Rendering coverage here includes render scale/upscale, MSAA, anisotropy, draw distance, expanded map loading, UI scale, unlocked FPS/sync/target, water/reflections/caustics, wind deformation, worker threads, smooth banding, texture brightness, vertex snapping, color-blind adjustment, both map-hiding systems and general diagnostics. The exact settings registry should remain the canonical enumeration rather than this narrative duplicating declaration metadata.

Lighting companion coverage must include sun lighting, interior brightness, point lights, emissive strength and leaf transmission, directional shadows/distance/resolution, ambient occlusion/strength/radius/quality and their debug views. Weather/environment companion coverage must include sky/day length/fixed hour, clouds/coverage/shadows, stars/nebula/aurora, horizon behavior, weather mode/intensity/buildup/lightning/sounds, fog/quality/density, area environments and wind forcing.

## Concrete simplification and documentation issues

1. Correct misleading tooltips: `skyHorizonAtEdge` currently describes automatic/fixed weather; `weatherSounds` describes water surface/bed. The point-light tooltip's blanket statement about no shadows also needs reconciling with wall/roof occlusion terminology.
2. Correct WaterMap's obsolete no-surface-geometry explanation. Following that comment leads a reader to the wrong rendering model.
3. Make setting change semantics explicit: live uniform, shader rebuild, target resize, scene reload or next natural reload. `hideUnrelatedMaps` is a concrete inconsistency to decide on.
4. Separate measurement modes in reporting: paced frame intervals, normal GPU queries and deliberately serialized GPU queries answer different questions. Never present them under an undifferentiated 'frame time'.
5. Keep surface emissiveness, placed point lights, room fill and thin-leaf transmission separate in both naming and controls. Similar visible brightness does not mean they share a light source.
6. Centralize water appearance constants only after identifying which artistic controls should exist. A wholesale abstraction without a clear behavior model would add complexity.
7. Do not infer dead code solely from class names or stale comments. This audit confirms contradictory documentation, but does not establish that entire legacy subsystems can safely be deleted. Trace callers and resource ownership before removal.

Visual acceptance remains open: inspect the user's ordinary playable scene, water at banks and waterfalls, thin transparent edges, swaying vegetation, map boundaries and changes between indoor/outdoor areas. Source inspection explains expected behavior; it does not certify the result looks good.
